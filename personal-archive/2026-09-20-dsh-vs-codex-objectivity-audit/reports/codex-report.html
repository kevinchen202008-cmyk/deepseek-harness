Executive summary

先看结论：两者并非完全同层竞争

DSH：可组装的 Agent 平台

更接近可自行部署、深度修改的 Agent 操作系统。优势是模型、工具、存储、沙箱、Agent Loop 和 UI 均可替换，适合建设自有平台。

Codex：产品化的编码 Agent

更接近开箱即用的工程生产力产品，同时开放 CLI、SDK 和 app-server 作为执行框架。优势是本地、IDE、桌面端和云任务体验完整。

核心判断：马上提高开发效率，优先 Codex；建设私有化、多模型、可深度改造的 Agent 平台，优先 DSH。实际落地可以采用“Codex 做开发执行，DSH 做业务编排”的组合方案。

User experience

用户使用体验：平台自由度与产品完成度的取舍

DSH 使用体验

优势：用户可以决定整个产品如何组合。Profile、Bundle 与 Patch 能定义不同 Agent 产品形态，同一套运行时可服务 Web、Headless、SDK 和自动化。

摩擦：普通用户需要理解 Node、pnpm、模型凭据、Profile 和运行目录。本机实例运行在 WSL，通过 127.0.0.1:3080 访问，当前仍需自行承担进程驻留和重启。

适合平台工程师适合研究团队高自由度

Codex 使用体验

优势：围绕代码库、任务、文件、Diff、终端、Review 和 Git worktree 构建统一体验，用户主要描述目标并审核结果。

摩擦：Cloud、账号、额度和服务可用性形成外部依赖；深入修改底层模型路由和运行语义的自由度有限。

适合开发者低上手成本本地 + 云端

Implementation architecture

实现架构：插件树与产品化执行框架

DSH：Cordis 插件树

Web / Desktop / CLI / SDK / ACP
↓
Profile + Bundle + cordis.patch.yml
↓
Agent Loop · Events · Tools · Session Log
↓
LLM · FS · Shell · Sandbox · Storage · Subagent
  • “一切皆插件”，不存在必须修改的特权核心。
  • 注册通过可撤销 effect 管理，插件卸载时回收。
  • 能力按 Service Definition / Provider / Consumer 拆分。
  • 追加式会话事件是恢复、审计和模型上下文的事实来源。

Codex：多界面共用执行框架

App / CLI / IDE / Cloud / 自定义产品
↓
SDK / app-server 客户端协议
↓
Agent Loop · State · Streaming · Tools · Approval
↓
OS Sandbox / Cloud Container · OpenAI Models
  • CLI、SDK 和 app-server 是开放组件。
  • app-server 暴露会话、轮次、流式事件、中断与审批。
  • 本地运行和托管 Cloud 使用不同隔离边界。
  • 模型访问、IDE 扩展和托管服务不属于完全开放的同一层。

说明：Codex 的比较范围限于官方公开的执行框架和产品接口，不推断未公开的模型服务内部实现。

Security & governance

安全治理：能力相似，成熟度与责任归属不同

DSH：部署者承担最终责任

  • 支持 read-only、workspace-write、danger-full-access。
  • Linux 使用 bwrap/Landlock，macOS 使用 Seatbelt，Windows 使用受限令牌/ACL。
  • 支持权限预设、一次性审批和自动化审批通道。
  • 官方安全说明明确标注：实验性、未安全审计，沙箱不是唯一安全边界。

Codex：默认治理更产品化

  • 沙箱与审批策略分层，默认限制网络和工作区外写入。
  • Cloud 任务运行于隔离容器，并区分设置阶段与 Agent 阶段。
  • 支持用户审批、自动审批审查与组织级受管配置。
  • 危险全权限模式仍需要用户主动选择，不能替代人工审查。

Decision guide

场景化选型建议

建设自有 Agent 平台

  • 需要完全自托管或严格控制数据流向。
  • 需要自由切换模型、存储、工具和执行后端。
  • 需要修改 Agent Loop、会话语义或多 Agent 协议。
  • 团队有能力承担平台工程与持续运维。

提高软件开发交付效率

  • 希望快速理解、修改、测试和 Review 代码。
  • 需要 Git worktree、Diff 与并行云任务。
  • 希望降低环境搭建和 Agent 运维成本。
  • 能够接受 OpenAI 账号、模型与托管服务边界。

DSH 编排 + Codex 执行

把 DSH 用作业务编排、会话持久化和多模型平台，把 Codex 用作编码执行 Agent。DSH 源码已包含 subagent-codex Provider，技术路线具备现实基础。

先按风险和责任选边界

敏感数据和核心业务先确定部署、凭据、审计与审批责任，再选择产品。不要仅按模型效果决定，也不要把任何 Agent 沙箱视为唯一安全控制。
