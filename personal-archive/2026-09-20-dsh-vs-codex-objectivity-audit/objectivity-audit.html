03逐项拆解

01 / 证据分级机制

谁标注了"这条结论我有多确定"

DSH 版 全文对关键论断标注 本机实测官方文档第三方 三级证据徽章，并单设"未能核实的事项"一节，列出具体未查证的数字（如上下文窗口传闻）。
Codex 版 没有逐条证据标注机制，仅在末尾附一句通用免责声明（"Codex 未公开部分不作推断"），读者无法分辨哪些结论有一手验证、哪些是转述。

可复核性上 DSH 版明显更透明：读者能沿着徽章找到证据来源，Codex 版则需要读者自行信任。

02 / 自我纠错记录

是否公开承认过判断错误

DSH 版 专设"对初版判断的三处更正"一节，明确写出此前误判——例如曾错误认为"Codex 无通用多代理编排原语"，复核后推翻，并保留旧结论以便追溯证据变化。
Codex 版 没有对应机制，报告以一次成型的结论呈现，读者无从判断其中是否也存在类似需要修正之处。

公开的自我纠错记录是少见的诚实信号，会主动暴露自身错误的报告，通常比不会犯错假象的报告更可信。

03 / 量化评分的方法论

数字是测出来的，还是"看起来像测出来的"

DSH 版 全部使用定性描述 + "DSH 赢 / Codex 赢 / 平手"徽章，不制造具体数值。
Codex 版 新增"能力侧写"评分板，给出如"底层可定制性 95""开箱体验 55"等两位数分值，虽注明"不代表模型质量基准"，但全文找不到评分权重或计算方法。

进度条 + 具体数字天然带来"精确测量"的错觉，而背后其实是主观定性判断的包装。这是一种常见的说服性呈现手法，而非客观分析。

04 / 呈现框架的中立性

版式和命名有没有替读者预先下结论

DSH 版 双方优劣势清单使用完全对称的视觉样式（.box.dsh / .box.cdx），配色权重一致。
Codex 版 "安全治理"一节把 DSH 一栏的样式类命名为 risks（暖色警示条），Codex 一栏命名为 pros（强调优点），即便两栏文字内容本身较为接近。

CSS 类名本身不会被读者看到，但它塑造的视觉基调会——这是一种结构性框架偏向，比文字措辞更隐蔽。

05 / 批评的对称性与具体性

说到对方（和自己）的缺点时，敢不敢给出可查证的细节

DSH 版 对 Codex 的缺陷给出源码路径（core/src/session/mod.rs）与四个具体 GitHub issue 编号；对自身也列出 5 条具体短板（审批仅两档、无保护路径等）。
Codex 版 双方缺陷均以概括性语言带过，没有引用具体源码、issue 或文档出处；对 Codex 自身"摩擦"仅用一句话概括。

可验证的具体批评（谁都能去查那个 issue 号）远比"较为复杂""存在依赖"这类泛泛而谈更有说服力，也更诚实。

06 / 结论胜负分布

谁赢得多，本身也是一种信号

DSH 版 用户体验表 + 架构表共约 20 行判断中，Codex 胜出与 DSH 胜出的数量大致相当，且主动收窄自身优势（"编排差距比初版描述的小"）。
Codex 版 13 行对比矩阵中，7 行判断栏明确写"Codex 更强/更领先/更成熟"，只有 3 行倾向 DSH，分布明显偏向自身所代表的一方。

单看胜负分布不能证明谁"对"，但一份自评报告如果结论几乎全部倒向自己，本身就是需要警惕的信号。
