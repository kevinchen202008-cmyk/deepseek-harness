4. 完整部署过程

检查 WSL 与目标环境

确认 Ubuntu 发行版、WSL2 内核、用户目录和磁盘空间可用；将部署目录选在 /home/kevin/apps，以获得 Linux 原生权限语义与更稳定的 Node 安装性能。

wsl.exe -d Ubuntu -- bash -lc 'grep PRETTY_NAME /etc/os-release; uname -r; df -h /'

结果：Ubuntu 24.04.4 LTS，WSL2 内核正常，磁盘空间充足。

确认项目运行时要求

根据仓库 package.json 校验 Node 与 pnpm 版本，避免因主版本不一致引发 lockfile 或原生模块问题。

# 项目声明
engines.node = "^22.19.0 || >=24.0.0"
packageManager = "pnpm@11.7.0"

# 实际环境
node --version   # v22.22.0
pnpm --version   # 11.7.0

结果：工具链与仓库声明一致。

获取官方源码

首次完整克隆在传输约 109 MB 后长时间无进展。停止该次任务创建的残留目录，经目标路径复核后改用浅克隆，降低传输量并保留部署所需的最新快照。

mkdir -p /home/kevin/apps
git clone --depth 1 https://github.com/deepseek-ai/deepseek-harness.git \
  /home/kevin/apps/deepseek-harness
git -C /home/kevin/apps/deepseek-harness rev-parse HEAD

结果：源码获取成功，提交为 c291e7961a515f6d7af9304e7fd1d257929aef26。

启用 Corepack 与固定 pnpm

通过 nvm 使用 Node 22.22.0，并启用项目指定的 pnpm 11.7.0。所有后续命令均先载入 ~/.nvm/nvm.sh。

. /home/kevin/.nvm/nvm.sh
corepack enable
corepack prepare pnpm@11.7.0 --activate
node --version
pnpm --version

首次依赖安装与网络诊断

初次使用镜像源安装时，原生模块 tarball 出现下载错误 23/超时；切换 npm 官方源后，在较高并发下仍可复现。随后单独下载约 8.5 MB 的 @rolldown/binding-linux-x64-gnu 包成功，证明基础网络和磁盘写入正常，问题更接近并发下载/存储路径组合。

判断：不是项目 lockfile 损坏，也不是磁盘不足；采用 WSL 内本地 store 和单并发安装是最小、可复现的处置。

清理未完成产物并低并发重装

仅清理本次克隆目录中的未跟踪生成物，保留 Git 追踪内容；随后明确指定 WSL 内 pnpm store、官方 registry 及下载/子进程并发度。

cd /home/kevin/apps/deepseek-harness
git clean -fdx

pnpm install --frozen-lockfile \
  --store-dir /home/kevin/.local/share/pnpm/store/v11 \
  --registry=https://registry.npmjs.org \
  --network-concurrency=1 \
  --child-concurrency=1

结果：1260 个包安装成功，用时约 10 分 15 秒；lockfile 供应链策略检查通过。darwin/arm64 工作区与循环依赖提示属于跨平台 monorepo 的预期告警。

执行全量构建

运行根项目构建脚本，依次完成 Linux x64 glibc 系统 addon、Host、Client、CLI 和 Web 前端构建。

cd /home/kevin/apps/deepseek-harness
. /home/kevin/.nvm/nvm.sh
pnpm run build

结果：构建退出码为 0；CLI 入口和 Web 静态产物均生成。仅出现弃用、插件耗时、bundle/chunk 大小类非阻断提示。

验证 CLI 与 Web 子命令

pnpm dsh --help
pnpm dsh web --help

结果：主 CLI 帮助正常；Web 子命令支持 --host、--port、--no-open 和 --trusted-host。

启动 Web 服务

采用本地回环地址启动，关闭自动拉起浏览器，并固定端口 3080。

cd /home/kevin/apps/deepseek-harness
. /home/kevin/.nvm/nvm.sh
pnpm dsh web --no-open --host 127.0.0.1 --port 3080

结果：Node 进程监听 127.0.0.1:3080；启动时生成的一次性/进程级访问令牌已从本报告中移除。

执行鉴权与页面验证

直接请求根路径返回 HTTP 401，证明匿名访问被拒绝；通过启动 URL 完成令牌交换并获得会话 Cookie 后，根页面返回 HTTP 200、text/html，响应体约 27,923 字节。

# 匿名检查（预期 401）
curl -i http://127.0.0.1:3080/

# 浏览器首次访问形式（报告内故意脱敏）
http://127.0.0.1:3080/?token=<redacted-process-token>

结果：访问控制与 Web UI 均验证通过。

8. 日常运维操作

8.1 启动

wsl.exe -d Ubuntu -- bash -lc '. /home/kevin/.nvm/nvm.sh; cd /home/kevin/apps/deepseek-harness; pnpm dsh web --no-open --host 127.0.0.1 --port 3080'

命令会占用当前终端并打印本次进程的令牌 URL。请勿将完整 URL 转发、截图到公共渠道或写入日志归档。

8.2 停止与检查

在承载服务的终端按 Ctrl+C 做优雅停止。检查端口：

wsl.exe -d Ubuntu -- bash -lc 'ss -ltnp "sport = :3080"'

8.3 更新源码并重建

  1. 先停止当前 Web 进程。
  2. 确认工作区没有需要保留的本地修改：git status --short。
  3. 执行 git pull --ff-only 获取上游变更。
  4. 使用已验证的低并发参数同步依赖，再执行全量构建。
  5. 重新启动服务，并重复端口、401 和浏览器页面检查。
cd /home/kevin/apps/deepseek-harness
. /home/kevin/.nvm/nvm.sh
git pull --ff-only
pnpm install --frozen-lockfile \
  --store-dir /home/kevin/.local/share/pnpm/store/v11 \
  --registry=https://registry.npmjs.org \
  --network-concurrency=1 \
  --child-concurrency=1
pnpm run build

9. 安全与敏感信息处理

  • 令牌脱敏：部署时生成的真实进程令牌未出现在本 HTML，统一表示为 <redacted-process-token>。
  • 凭据最小暴露：只检查 ~/.dsh/.credentials.yaml 是否存在，未打开或导出文件内容。
  • 网络最小暴露：服务绑定 127.0.0.1，默认不对局域网其他设备开放。
  • 匿名拒绝：HTTP 401 属于预期保护；不要通过关闭鉴权来绕过。
  • 报告边界：HTML 内不包含密码、API Key、Cookie、访问令牌或完整启动日志中的敏感查询参数。
如果后续需要将服务开放到局域网或公网，应先引入 TLS、可信反向代理、访问控制、令牌轮换和最小权限策略；当前部署不应直接暴露到公网。
